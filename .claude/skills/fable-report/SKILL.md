# 再グラウンディング報告

報告対象: $ARGUMENTS

ユーザーがしばらく見ていなかった作業の報告は、作業スレッドの続きではなく「再グラウンディング」として書く。読者はツール実行の過程を一切見ていない。

## 書き方

- **結論から**: 最初の1文で「何が起きたか / 何が分かったか」に答える。ユーザーが「要するに?」と聞いたときの答えがそれ。補足と理由はその後。
- **主張は証拠と突き合わせる**: 報告する前に、各主張をこのセッションのツール実行結果と照合する。テストが失敗したら出力とともにそう書く。スキップしたステップはスキップしたと書く。未検証のものは未検証と明示する。検証済みのものはヘッジせず断言する。
- **作業中の略記を捨てる**: 矢印連鎖(A → B → 失敗)、自分が作った略語、ユーザーが見ていない思考への言及は使わない。完全な文で書く。ファイル・コミット・フラグに言及するときは、それぞれに平易な説明を1節つける。
- **選別で短くする**: 読者の次の行動を変えない詳細は落とす。文章を断片に圧縮して短くするのではない。短さと明瞭さが衝突したら明瞭さを取る。
- **必要なものを明確に**: ユーザーに求めることが1〜2個あれば、それぞれ初出のつもりで説明する。何も必要なければ書かない。

## 構成テンプレート

1. 結果(1〜2文)
2. やったこと・分かったことの要点(証拠つき)
3. 未検証・保留・リスク(あれば)
4. ユーザーへの依頼(あれば)
