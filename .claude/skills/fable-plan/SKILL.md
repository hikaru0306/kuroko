# フェーズ計画(検証可能なチェックポイント方式)

## タスク

$ARGUMENTS

巨大なプロンプト1つで進めるのではなく、各フェーズが「次のフェーズ開始前に(できれば自動で)検証できる成果物」を生むように計画を設計する。

## 手順

1. 関連コードや資料を調査し、タスクの実像を掴む(調査が広範ならExploreサブエージェントに委譲)。
2. ゴールと成功基準を1〜3行で定義する。成功基準は観測可能な事実(コマンドの結果、テストの合否)で書く。
3. フェーズに分割する。各フェーズには以下を必ず含める:
   - 成果物(ファイル、機能、レポートなど具体物)
   - 検証方法(実行するコマンド、確認する観測結果)
   - 依存関係(並列実行できるものは明示し、サブエージェント委譲候補にする)
4. `memory/plan-<タスク名>.md` にチェックボックス形式で保存する。
5. 計画の要点(フェーズ数、最初の一手、リスク)を短く報告する。

## 注意

- 計画は最小限に。仮定の将来要件のためのフェーズは作らない。
- ユーザーにしか答えられない曖昧さがあれば、計画確定前にまとめて質問する。
- 実行まで依頼されている場合は、計画保存後そのまま /fable-run の原則で実行に移る。
