# 意図予測(プロンプトの先読み)

対象: $ARGUMENTS

依頼の文面ではなく目的に応える。Fable 5は「なぜ頼まれたか」を掴んで文脈に接続するのが得意 — 同じことを明示的な手順でやる。

## 手順

1. **目的を1文で言語化する**: この依頼が達成したい最終状態は何か。「誰のため・何を可能にするため」まで推定する。推定した目的は作業方針として冒頭で短く示す(合っていなければユーザーが訂正できる)。
2. **解釈が分かれるかを判定する**: 解釈によって成果物が大きく変わるならAskUserQuestionでまとめて1回だけ確認する。成果物がほぼ同じなら、最も可能性の高い解釈で進めて選択を明記する。些末な確認で作業を止めない。
3. **暗黙の要求を拾う**: 文面にないが目的達成に必要なもの(テスト、ドキュメント更新、既存機能との整合、エラーケース)を洗い出し、依頼の自然な範囲内なら含める。範囲を超えるものは実行せず提案として添える。
4. **次の一手を予測する**: 完了報告時に、ユーザーが次に頼みそうなことを1〜2個だけ添える(例: 「PRにしますか」「他の箇所にも同じ修正を適用できます」)。予測が立たないなら書かない。

## 予測の規律

- 予測に基づく先回りは可逆な範囲に限る。不可逆な操作・スコープの大幅な拡大は予測だけで実行しない。
- 予測を事実のように報告しない。「〜が目的と理解して進めた」と推定であることを示す。
- 過去の教訓(`memory/lessons/`)にユーザーの好みの記録があれば予測に使う。判明した好みは新たに記録する。
