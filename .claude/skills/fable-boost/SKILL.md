# Fable 5ギャップ補正ハーネス

対象タスク: $ARGUMENTS

Fable 5が優れているのは「初回正答率」「長期の一貫性」「曖昧さの処理」。これらは追加の計算と検証で相当程度補える。1回の生成に賭けず、生成回数と検証回数で品質を買う。

## 手順

1. **着手前の文脈収集を倍にする**: 関連コード・過去の類似実装・呼び出し元をすべて読んでから書き始める。Fable 5が暗黙にやる文脈把握を、明示的な調査で代替する。広範ならExploreサブエージェントに委譲。
2. **複数候補 + 審査**: 設計判断が分かれるタスクでは、異なる方針の候補を2〜3案作り(必要ならサブエージェントで並列生成)、仕様への適合・単純さ・エッジケース耐性で採点して最良案を選ぶ。次点の良い部分は取り込む。
3. **一発正答を狙わない**: 実装 → 実際に動かす → 失敗を直す、のループを最初から計画に入れる。「動かして確かめる」を省略しない。
4. **検証を外部化**: 完了主張の前に /fable-verify で別コンテキストの検証者にかける。自己確認だけで完了と言わない。
5. **長期一貫性はメモリで補う**: 長いタスクでは決定事項・却下した案・残作業を `memory/plan-*.md` に都度書き出し、各フェーズ開始時に読み直す。コンテキストの劣化をファイルで補正する。

## エッジケース点検(実装タスク用)

書き終えたら次を機械的に点検する: 空入力・境界値・重複・並行実行・失敗パスの後始末・既存呼び出し元への影響。該当しない項目はスキップしてよいが、点検自体は省略しない。
