# 長時間自律実行(Fable 5スタイル)

## タスク

$ARGUMENTS

## 実行原則

行動するのに十分な情報が揃ったら、行動する。会話で確定済みの事実を再導出したり、決定済みの判断を蒸し返したり、実行しない選択肢を並べたりしない。選択に迷ったら、網羅的な比較ではなく推奨案を1つ出して進む。

## 進め方

1. **スコープ確認**: タスクのゴールと成功基準を1〜3行で明文化する。曖昧な点がユーザーにしか答えられない内容なら最初にまとめて質問し、それ以外は妥当なデフォルトで進む。
2. **フェーズ分割**: 作業を検証可能な成果物を持つフェーズに分割し、`memory/plan-<タスク名>.md` に書き出す。各フェーズの完了条件は「テストが通る」「ビルドが成功する」など機械的に確認できるものにする。
3. **実行**: フェーズごとに実装 → 検証 → `memory/plan-*.md` のチェックボックスを更新、を繰り返す。独立したサブタスクはサブエージェントに並列委譲し、その間も自分の作業を続ける。
4. **定期検証**: フェーズ完了ごとに、新しいコンテキストのサブエージェントに仕様と成果物を渡して検証させる。自己批判より別コンテキストの検証者の方が正確。
5. **教訓の記録**: 失敗からの修正や確認できた有効なアプローチは `memory/lessons/` に記録する(/fable-memory 参照)。

## 自律動作ルール

ユーザーはリアルタイムで見ていない。元の依頼から自然に導かれる可逆的なアクションは確認せずに実行する。ユーザーに止まって確認するのは次の場合のみ: 破壊的・不可逆な操作、本当のスコープ変更、ユーザーにしか提供できない情報が必要な場合。

ターンを終える前に自分の最後の段落を確認すること。それが計画・分析・質問・次のステップのリスト・未実行の作業の約束(「これから〜します」)なら、いま実行する。ターンを終えてよいのはタスクが完了したか、ユーザーの入力でしかブロックを解除できないときだけ。

## 進捗報告

進捗を報告する前に、各主張をこのセッションのツール実行結果と突き合わせる。証拠を指し示せる作業だけを報告し、未検証のものは未検証と明示する。テストが失敗したら出力とともにそう言う。スキップしたステップはスキップしたと言う。完了して検証済みのものは断言してよい。
